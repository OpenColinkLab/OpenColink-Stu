PAGE 02 · C IMPLEMENTATION

事件 + 函数指针 + 转移宏

C 实现不保存状态编号，而是保存“当前状态处理函数”的地址。切换状态就是改写一个函数指针。

2.1

最小类型协议

typedef status_t (*State_Handler)(
    FSM_t *this_p,
    event_t const *evt
);

struct FSM_t {
    State_Handler state_handler;
};

/* target() 返回 TRAN_STATUS 时，
   派发器执行 EXIT → ENTRY */
2.2

三个指针分别指向谁

FSM_t *this_p 指向对象内存

this_p->state_handler 访问对象中的函数指针成员。

State_Handler 指向函数代码

保存 Proj_Idle、Proj_StartGame、Proj_Check 的入口地址。

event_t const *evt 指向只读事件

通过 evt->signal 读取信号，但状态函数不能改写原事件。

2.3

Macro · Assignment · Comma operator

转移宏先改函数指针，再返回 TRAN_STATUS

#define SOL_FSM_Tran(this_p, target) \
    (((FSM_t *)(this_p))->state_handler = \
        (State_Handler)(target), TRAN_STATUS)

/* 正确调用 */
return SOL_FSM_Tran(this_p, Proj_Check);
01(FSM_t *)(this_p)

地址不变，按 FSM 基类布局访问。

02->state_handler

找到保存当前状态函数地址的成员。

03state_handler = target

把目标状态函数地址写进去。

04(assignment, TRAN_STATUS)

逗号取右值，整个表达式等于 TRAN_STATUS。

逗号运算符是什么

(left, right) 先完整求值左边，丢弃左边结果，再求值右边；整个表达式的结果来自右边。

int a = 0;
int value = (a = 3, a + 2);
/* a == 3, value == 5 */

放到宏里就是

return (
    state_handler = Proj_Check,
    TRAN_STATUS
);

左边完成状态切换，右边让派发器知道“发生了转移”。缺少 return 时指针会改，但 EXIT/ENTRY 不会执行。

2.4

派发器保存旧函数地址

1previous = state_handler

先保存旧状态函数地址。

2result = previous(this, evt)

把当前事件交给旧状态。

3previous(this, EXIT)

返回 TRAN 时先清理旧状态。

4state_handler(this, ENTRY)

再进入已经写好的新状态。

原工程把项目处理函数强转成基类函数指针。常见 ARM/Windows ABI 上可运行，但严格 C 标准下属于未定义行为；高可靠性代码应使用统一签名包装函数。

三个处理函数，一条固定模板

每个状态都先处理 ENTRY/EXIT，再看业务信号。区别只在业务分支里的条件和动作。

switch (evt->signal) {
case ENTRY_SIG:  /* 进入动作 */ return HANDLED_STATUS;
case EXIT_SIG:   /* 退出清理 */ return HANDLED_STATUS;
case IS_GAME_SIG:/* 业务判断 */ break;
default:         return IGNORED_STATUS;
}

01START_GAME生成

nextTurn 为真时生成地鼠：随机 500–1900 ms 准备延时，随机洞位，清超时和等待令牌，再进入 CHECK。

nextTurn 为假时只补循环，不生成新股，因此按 4/8 不重置当前地鼠。

4.1

验证覆盖

  • 开始键生成合法洞位和 500–1900 ms 延时
  • 正确键加 1 分，错误键加 1 失分
  • 第 500 个 tick 触发超时并进入下一轮
  • 键值 4/8 不改变当前地鼠和分数
  • 相同 seed 的洞位与延时完全一致
  • 退出后回到 IDLE 并清除地鼠
4.2

三个易错点

  • 转移宏没有 return，EXIT/ENTRY 永远不会执行。
  • 把准备延时和 500 ms 反应窗混成一个计时器。
  • 在 ISR 中直接执行蜂鸣、GPIO 和完整状态动作。
