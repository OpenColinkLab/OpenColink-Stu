# 哔哩哔哩视频下载器 1.3.1

> 本 OpenColink-Stu 源码副本按维护者要求省略了部分图片，保留上传时已经完成的图片及小型矢量图标。需要完整本地图片时，请向维护者取得原项目图片目录；图片相关检查应在资源恢复后执行。

**bilibili-video-downloader 是一个专门用于下载哔哩哔哩（B 站）视频的简体中文桌面工具。** 项目仅以哔哩哔哩视频下载为使用和维护范围。

**优酷视频下载功能已废弃，不再支持或维护。** 当前 1.3.1 源码及应用中可能仍有旧版优酷入口或实现，这些属于历史遗留内容，请勿使用；不应将本项目视为优酷或其他平台的下载器。

当前发行版为 **macOS Apple Silicon（ARM64），要求 macOS 13 或更新版本**。应用内置 yt-dlp、FFmpeg、FFprobe，直接使用不需要安装 Node.js、Python 或其他开发工具。

## 下载与安装

1. 前往 [Releases](https://github.com/wangchuanao2008/bilibili-video-downloader/releases/latest)，下载 `bilibili-video-downloader-v1.3.1-macos-arm64.zip`。
2. 解压后，将 `视频下载器.app` 拖入「应用程序」，双击运行。
3. 本版本未进行 Apple Developer ID 签名和公证；其他 Mac 上可能出现系统安全提示。
4. Release 提供 `SHA256SUMS.txt`，可使用 `shasum -a 256` 核对下载文件。

## 直接使用

- 应用：Release 压缩包内的 `视频下载器.app`，双击打开。应用内置运行组件，无需安装开发依赖。
- 粘贴完整的哔哩哔哩视频页面 HTTPS 链接，例如 `https://www.bilibili.com/video/BV…`，点击「下载视频」或按 Enter。
- 默认保存到 `~/Downloads/视频下载器`。点击输入框下方的保存位置可修改，新任务会使用新位置。
- 默认选择来源最佳画质。展开「高级选项」→「解析清晰度」，可从实际提供的分辨率中选择。
- 添加多个任务后，后台最多同时解析两个视频，等待下载的任务也会提前显示来源提供的标题、封面和时长。文件仍按加入顺序逐个下载。正在解析、排队、下载、合并或校验的任务都可取消；失败和取消的任务可以重试。
- 完成后的播放按钮调用系统默认播放器，文件夹按钮在 Finder 中定位视频。
- 左下角可选择浅色、深色或跟随系统。下载记录、保存位置和主题都保存在本机。

分离音视频默认无损合并为 MKV；直接文件保留原格式，不强制转码。如果系统默认播放器不支持某些格式，请使用兼容的播放器。来源没有音轨时，不会凭空添加声音。

取消任务可能留下 `.part` 等临时文件；1.1.0 重试会重新解析并使用新文件名，避免复用旧试看文件。删除记录只移除应用记录，不删除视频和临时文件。重试使用原任务的保存位置；切换保存位置后请重新粘贴链接创建新任务。关闭窗口即退出应用；有未完成任务时会提醒，下次启动可重试。

## 支持范围与验证说明

- 使用范围：哔哩哔哩单个视频页面、B 站账号登录授权、来源实际提供的清晰度选择、多任务排队、取消和重试。
- 需要账号权限的视频仅使用你已经拥有的观看权益；不绕过付费、DRM、地区或其他访问控制。不支持直播和整份播放列表。
- 优酷及其他平台不在本项目的支持和维护范围内。
- 已有自动测试覆盖下载引擎、分离音视频合并、清晰度选择、队列、取消、重试、持久化、界面及 B 站授权存储。测试中的本地视频和公开直链仅用于验证底层引擎，不代表支持其他视频平台。
- B 站登录的自动测试使用虚构凭据；真实扫码登录及有权限视频的完整下载仍需使用自己的账号验证，未将该环节列为已通过。

遇到错误时，界面会区分无效网址、失效视频、网站不支持、登录/访问限制、网络故障、目录权限、磁盘空间和组件缺失，提供下一步提示；原始错误可在任务「技术日志」中展开。磁盘不足及部分权限错误通过错误分类测试覆盖，未通过填满实际磁盘等破坏性方式模拟。

## 多任务信息预加载（1.2.0）

解析队列与下载队列独立运行。任务显示“等待解析 → 正在解析 → 等待下载”，无须等前一个视频下载完成才能查看信息。来源未提供封面或时长时保留占位，不编造信息。解析超过五分钟的等待任务会在下载前重新获取信息；登录状态变化也会刷新等待中的 B 站任务。实际媒体地址由下载引擎在开始下载时重新提取。取消、移除或重试后，旧解析结果不会覆盖新状态。

## B 站登录授权（1.1.0）

1. 点击左侧“登录 B 站”，在独立的 B 站官方窗口自行扫码或输入凭据。不要向聊天发送密码或 Cookie。
2. 登录成功后，窗口自动关闭，左侧显示账号名称。若状态未刷新，可点击旁边的刷新按钮。
3. 登录账号须拥有目标视频的完整观看权益。登录本身不会获得充电权益。
4. 对之前的试看下载，点击记录上的“重新下载”，或重新粘贴链接。旧文件保留，新下载使用不同文件名。
5. 切换账号会先清除旧授权并取消 B 站任务；“退出”会清除本机授权并取消 B 站任务。不会代替你注销网站账号。

登录窗口没有 Node 权限和应用 IPC，仅允许跳转到 HTTPS B 站页面；状态通过官方账号接口确认。浏览器会话使用内存分区，持久化 Cookie 用 Electron safeStorage 在本机加密保存（`bilibili-auth.enc`）。系统加密不可用时仅保留本次会话，不存明文。为 yt-dlp 临时导出仅限 B 站域名的 Cookie 文件，权限 0600，父目录 0700，每次子进程结束后删除；异常退出的残留在下次启动清理。仅对 HTTPS B 站任务传递 Cookie，日志隐藏凭据和 URL 查询参数。

充电专属页面显示当前账号无完整观看权限时，解析阶段直接提示；遇到页面访问限制，仍会在成品校验阶段检查时长，防止把试看误报为完整下载。没有元数据时长的来源无法做时长比对。旧版 B 站历史记录会显示“未校验完整时长”，不会自动删除原文件。

本次自动测试使用虚构凭据，验证了登录状态、加密存储及退出清除。实际扫码和目标视频完整版下载需要你用自己的有权限账号完成，未把该环节列为已通过。

## 源码与开发

架构：Electron 主进程 + React / TypeScript 界面 + 独立 yt-dlp / FFmpeg 进程。源码保留部分旧版优酷实现及测试，仅作为历史遗留内容；后续开发以哔哩哔哩功能为准。

```sh
npm ci
npm run setup:binaries
npm run build
npm start
npm test
npm run test:e2e
node --import tsx tests/auth-e2e.ts
node --import tsx tests/queue-e2e.ts
npm run dist
```

`setup:binaries` 下载固定版本并校验 SHA-256，仅适用于 macOS ARM64。源码目录不再重复保留运行组件；开发或测试前请执行 `npm ci` 和 `npm run setup:binaries`。现成 App 不受影响。测试会创建仅监听 127.0.0.1 的视频服务器；受限制的沙盒中执行需要系统权限。测试结果、下载样本和截图位于 `test-artifacts/`，不会混入正式历史。

- `electron/engine.ts`：解析、队列、子进程、实际进度、合并、文件校验、封面、错误分类和持久化。
- `electron/main.ts` / `preload.ts`：受限 IPC、原生目录选择、剪贴板和打开文件。
- `src/main.tsx` / `style.css`：中文界面与主题。
- `tests/`：真实引擎及 Electron 界面测试。
- `resources/binaries.json`：运行组件固定版本、来源和校验值。

渲染进程开启 `contextIsolation` 和沙盒，禁用 Node 集成和外部导航；网址仅接受 HTTP/HTTPS，所有下载命令使用参数数组，不经过 shell。文件名由引擎清理，并加入独立任务标识，不覆盖同名文件。任务进度来自 yt-dlp，音视频分开下载时百分比是**当前流**的进度；未知速度、大小和剩余时间保持空缺。输出完成后实际检查视频流、预期音轨、文件大小及源视频与成品时长。短于源视频超过 max(5 秒, 1%) 会显示不完整。

本地设置和记录保存在 Electron 的用户数据目录（本机构建为 `~/Library/Application Support/视频下载器/state.json`），不上传。任务记录中含原始网址、路径和技术日志，应按个人数据保管。

## 开发环境与依赖恢复

在本项目目录执行开发命令。使用 Node.js 22.12+ 和 npm；保留并提交 `package-lock.json`，首次下载或同步依赖后运行 `npm ci`。不要提交 `node_modules/`。更新依赖时使用 `npm install` 并同时审阅清单和锁文件的变化。构建目录不能代替源码。

## 首次源码安装的工具链

使用 Node.js 22.12+、npm，在项目根目录执行上述命令并提交 `package-lock.json`。`npm ci` 安装 Electron 等开发依赖；`npm run setup:binaries` 另外下载应用运行需要的媒体组件，两步不可互相替代。界面验收使用 Playwright，首次运行前执行 `npx --no-install playwright install chromium`。macOS ARM64 之外的平台不要使用 ARM64 二进制初始化脚本；Windows 资源使用独立的 `npm run setup:windows` 和对应构建配置，未在此次审计中验收。
